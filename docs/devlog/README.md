# 开发日志

记录每一次开发任务“做了什么、怎么验证的、留下了什么问题”。它是过程留痕，和另外两类文档分工如下：

| 文档 | 回答的问题 | 粒度 | 能否修改 |
| --- | --- | --- | --- |
| [CHANGELOG.md](../../CHANGELOG.md) | 这个版本对用户、接入方、协议有什么变化 | 每个版本 | 未发布部分随时改；已发布版本不改 |
| [docs/adr/](../adr/README.md) | 为什么这样设计，放弃了什么 | 每个架构决策 | 已采纳后不改正文 |
| 开发日志（本目录） | 这次任务的目标、改动、验证结果、遗留问题 | 每次任务 | 只追加；事后发现错误时在文末补“更正” |

## 什么时候写

- 由编码 Agent 完成的任务，**每次都写**（人工复核时靠它还原过程）；
- 人工开发：跨多个提交、改了约束或协议、排查过线上 / 联调问题时写；一两行的小修可以不写。

## 命名与格式

文件名 `YYYY-MM-DD-英文短横线主题.md`，同一天多篇用不同主题区分。正文用下面的模板，没有内容的小节写“无”，不要删：

```markdown
# YYYY-MM-DD 主题

- 执行：人名 / Agent（模型名）
- 关联：提交哈希、ADR-NNNN、CHANGELOG 条目（没有就写“无”）

## 目标
一两句话：要解决什么问题，范围到哪里为止。

## 改动
按文件或模块列出改了什么、为什么。

## 验证
实际运行过的命令和结果（通过 / 失败及原因）。没运行的检查要写明没运行。

## 遗留问题
发现但没处理的问题，写清位置和建议做法；处理后在后续日志里引用本篇。
```

提交信息正文末尾写上对应日志的路径，便于从 `git log` 反查。
