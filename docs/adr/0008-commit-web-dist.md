# ADR-0008 工作台构建产物 `web/dist` 随代码提交

- 状态：已采纳
- 日期：2026-10-28（2026-10-29 补记）
- 相关：AGENTS.md“仓库卫生”、`.gitignore`、`agent/server.py`（`/workbench/` 静态目录）

## 背景

部署和联调机器上通常只有 Python。工作台是 React + Vite 项目，构建需要 Node.js 20.19 / 22.12 以上。仓库没有 CI 流水线来产出构建包（2026-10-29 加的 CI 只检查 dist 与源码一致，不产出构建包，见 ADR-0010）。

## 决策

- `web/dist/` 随源码提交，Agent 服务直接以静态文件提供 `/workbench/`。
- 改了 `web/src/`（或前端依赖）后，必须 `npm run build` 并把 dist 一并提交，保证运行的页面与源码一致。
- `.gitignore` 里保留了注释掉的 `web/dist/`，改为流水线构建时取消注释即可。

## 考虑过的其他方案

- 部署时现场构建：部署机需要 Node 和网络访问 npm。
- 发布包附带构建产物、仓库不提交：需要 CI 和制品库，当前没有。

## 后果

- 好处：克隆后 `pip install` + `python run.py` 即可运行。
- 代价：提交差异里有构建产物噪音；忘记重建会导致页面与源码不一致，测试不依赖 dist，由 CI 的 dist 一致性检查兜底（ADR-0010）。
- 后续：有 CI 后可改为流水线构建，届时写新 ADR 取代本篇。
