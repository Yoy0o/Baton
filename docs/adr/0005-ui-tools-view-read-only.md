# ADR-0005 界面工具只能是 `view` / `read`

- 状态：已采纳
- 日期：2026-10-28（2026-10-29 补记）
- 相关：AGENTS 约束 4、ARCHITECTURE 3.4、INTEGRATION_RULES R5.2、`agent/manifest.py`、`agent/providers/bridge_provider.py`

## 背景

界面工具由业务系统页面通过桥接 SDK 注册，在用户浏览器里执行。平台看不到它内部做了什么，无法对它做预览、回放参数或幂等；页面也可能注册清单之外的工具。如果允许界面工具写业务数据，ADR-0003 的确认机制就有了旁路。

## 决策

- 页面能注册的工具必须在清单 `ui_bridge.tools` 白名单中声明，未声明的注册时被拒绝。
- 界面工具的风险等级以清单为准，只能是 `view`（只改界面）或 `read`（只读界面状态），由 `manifest.py` 的类型约束强制。
- 业务写入一律走 API 的预览 / 提交。

## 考虑过的其他方案

- 允许界面工具声明 `write` 并走确认：平台无法验证页面实际执行的内容与确认内容一致。
- 不设白名单、信任页面注册：页面被改动或注入时工具集会失控。

## 后果

- 好处：`/api/ui-actions` 可以安全地让用户直接调用界面工具（不经确认）；界面能力的风险面很小。
- 代价：只在前端存在的写能力无法接入，需要系统补 API。
- 后续：无。
