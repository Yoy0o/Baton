# ADR-0007 事件即真相：工作台单一 reducer，实时与重放同一逻辑

- 状态：已采纳
- 日期：2026-10-28（2026-10-29 补记）
- 相关：AGENTS 约束 6、ARCHITECTURE 3.5 / 3.6、`agent/runtime.py`、`agent/conversations.py`、`web/src/store.ts`

## 背景

v0.2 要求刷新页面、切换对话、断线重连、服务重启之后，看到的执行过程、确认卡片、答复与实时看到的一致。如果实时渲染和历史渲染是两套代码，两者迟早会出现差异；如果历史另存一份“视图快照”，又要维护两种数据结构的同步。

## 决策

- 运行时推送的事件就是对话的事实记录。需要重放的事件带递增 `seq`，写入 `data/conversations/<对话 ID>.json`；逐字输出等临时事件（`conversations.EPHEMERAL_EVENTS`）不保存，最终文本由 `thought` / `message` 保存。
- 工作台只有一个 reducer（`web/src/store.ts`）：实时事件与打开历史对话时拉取的事件列表都交给它。
- 打开对话期间到达的实时事件先缓存，快照应用后再补上，按 `seq` 去重；`seq` 只增不减。
- 新增事件类型时，同时改 `runtime.py` / `conversations.py`、`store.ts`，并更新 ARCHITECTURE 3.5 的事件表。

## 考虑过的其他方案

- 服务端保存渲染好的视图状态：要为每种界面变化写状态迁移，与实时渲染逻辑重复。
- 只保存模型历史、重放时重建界面：模型历史里没有确认卡片、耗时、系统标识色等界面信息。

## 后果

- 好处：实时与历史天然一致；中断、停止、重新生成都表现为事件，可如实还原。
- 代价：事件格式成为前后端共同契约，改字段要两边同步；对话文件随事件增长。
- 后续：可映射到 AG-UI 事件模型（ARCHITECTURE 第 7 节），边界不变。
