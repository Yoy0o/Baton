# ADR-0001 用 ADR 记录架构决策

- 状态：已采纳
- 日期：2026-10-29
- 相关：AGENTS.md“文档与留痕”

## 背景

v0.2 的关键设计（网关唯一入口、写操作两段式、结果引用等）散落在 README、ARCHITECTURE 和代码注释里，只写了“是什么”，没写“为什么”和“放弃了什么”。仓库会由人和编码 Agent 交替修改，Agent 读到约束时不知道代价，容易为了一个局部需求放宽约束；人回头看时也说不清当初的取舍。

## 决策

- 在 `docs/adr/` 下用一篇一个决策的方式记录架构决策，格式见 `template.md`，索引在 `README.md`。
- 已采纳的 ADR 只追加、不改正文；推翻时写新 ADR 并标注取代关系。
- v0.2 已生效的基线决策补记为 ADR-0002 至 0009。
- 与之配套：用户可感知的变化记 `CHANGELOG.md`，每次开发任务的过程和验证记 `docs/devlog/`。三者分工见 AGENTS.md。

## 考虑过的其他方案

- 只在 ARCHITECTURE 里加“设计理由”小节：会和“现状说明”混在一起，决策被推翻时理由也跟着被改掉，失去历史。
- 只靠提交信息：查找困难，跨多个提交的决策没有落点。

## 后果

- 好处：改约束前有据可查；Agent 能在动手前读到理由。
- 代价：每个架构级改动多写一页文档。
- 后续：无。
