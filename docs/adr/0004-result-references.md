# ADR-0004 大数据走 `result_id` 引用，模型只看摘要和预览

- 状态：已采纳
- 日期：2026-10-28（2026-10-29 补记）
- 相关：AGENTS 约束 3、ARCHITECTURE 3.2、INTEGRATION_RULES 第 4 节、`agent/results.py`、`agent/contracts.py`

## 背景

典型任务要在系统之间传递几十到几千条记录（排班名单 → 位置 → 分组 → 写回）。把整份列表放进模型上下文会：占满上下文、拖慢响应、增加费用；让模型抄写 ID 时出错；诱导模型“心算”统计和分组。

## 决策

- 工具返回的列表由网关存入结果仓库，模型只拿到 `result_id`、摘要、总数、字段名和最多 5 条预览（`contracts.PREVIEW_ROWS`）。
- 下一步工具的参数要接收上一步结果时，在清单里声明 `accepts_result`（`ids` / `rows` / `geojson` / `group_plan`），模型直接传 `result_id`，转换在网关做。
- 统计、分组等计算交给内置工具，不让模型自己算。
- 浏览器端（地图页面、工作台“结果”页签）通过 `GET /api/results/{id}` 读取完整数据。
- 单个结果最多 5000 行（`results.MAX_ROWS`，R2.4），默认保存 24 小时。

## 考虑过的其他方案

- 直接把数据给模型、靠大上下文模型处理：成本和准确性都不可控，小模型无法使用。
- 由模型生成代码处理数据（程序化工具调用）：需要沙箱，v0.2 不做。

## 后果

- 好处：上下文大小与数据量无关；跨系统传递不经模型抄写；数字来自工具而不是模型。
- 代价：每个需要接收结果的参数都要在清单里声明转换方式；结果有保存期限和行数上限。
- 后续：无。
